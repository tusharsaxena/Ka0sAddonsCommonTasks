# #83 FTUX: a shared guided tour and key-settings setup for every addon

## Summary

Add a shared **first-time user experience (FTUX)** to LibKa0s that every Ka0s addon can opt into: a guided tour of what the addon does and how it works, ending in a simplified interface for assigning the addon's key settings.

## Motivation

Each Ka0s addon has a full settings panel built from its schema, but a new user meets every option at once, with no explanation of what the addon is for or which settings matter. A shared FTUX would give every addon the same short, guided first run, without each one building its own.

## Proposed shape

- **A guided tour.** Each addon declares a few steps: a title, body text, and optionally a frame or region to highlight. Together they cover what the addon does, how it works, and where its controls live. The steps can be Back/Next/Skip.
- **Key settings, simplified.** A final step (or steps) shows a small set of settings the addon marks as "key". These are drawn from the existing schema rows, so there is one source of truth, and rendered with plain controls and short descriptions. They write through the normal settings path.
- **First-run trigger.** The FTUX shows once on the first login after install, records that it was seen in the addon's saved variables, and can be reopened from a slash verb (for example `/<prefix> tour`) and from a button on the settings panel.
- **Library-owned, addon-declared.** LibKa0s owns the window, navigation, highlighting, skinning (Skin/SkinPaint) and locale plumbing. The addon supplies only its step declarations and its list of key setting ids.

## Open questions

- Is the key-settings list a new flag on schema rows, or a separate list the addon passes in?
- Should it stay out of the way in combat and lockdown? Probably defer, as the toasts and settings panel do.
- Should it come back after a major version with new key settings ("what's new"), or stay first-run only?
- Does this need a new rule in the Ka0s WoW Addon Standard so every addon in the roster adopts it, and if so, which section?

## Acceptance

- A LibKa0s API that an addon can call with steps and key setting ids, with docs in `docs/api/`.
- It shows once on first run, can be reopened by a slash verb and a panel button, and follows the active skin and locale.
- Headless tests in the kit, and one addon (for example QuickComms) adopting it as the reference consumer.
