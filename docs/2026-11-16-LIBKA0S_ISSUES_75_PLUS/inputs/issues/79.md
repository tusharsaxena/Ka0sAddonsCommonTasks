# #79 DebugLog: report seam (dumps and lists to the console, one chat pointer) with plain-text Copy, rolled out to every Ka0s addon

## Summary

The owner ruled on 2026-11-08 that multi-line **reports** (dumps and lists a player asks for to inspect or share) go to the debug console, not to chat. ConsumableMaster implements it first, addon-locally. This issue moves it into `LibKa0s-DebugLog-1.0` and rolls it out to every Ka0s addon. It also fixes the one thing the addon cannot fix on its own: the console's **Copy** text carries color codes.

## The ruling (owner, 2026-11-08)

- **Chat**, through the addon's tagged printer: acknowledgments and short answers (one or two lines), refusals and errors (combat, unknown verb, usage, disabled, library missing), the help index, and the reserved `/<slash> list` verb. The owner chose to keep `list` in chat.
- **Debug console**: every report, meaning any multi-line read-out: every `dump` target, `priority … list`, `aio … list` and similar lists, diagnostics, and perf reports.
- A report is written **whether or not trace logging is on**. It is not a trace.
- The console **opens if it is hidden**.
- Chat gets **exactly one** pointer line naming the report and its line count, for example `dump bags: 23 lines written to the debug console. Use Copy to share it.` This matches the diagnostics report's line.
- Usage and refusal lines inside a report verb stay in chat and write no report.
- Without the library, the stub falls back to printing the report in chat, with no pointer.

## The reference implementation

ConsumableMaster commit `9d2b26e`, on branch `feat/2026-11-08-forever-port`:

- **The seam.** `KCM.DebugLog.Report(tag, title, fn) -> n` in `core/DebugLogSetup.lua`:
  - `fn(out)` writes the body.
  - Lines are collected first, so a refusal produces no report.
  - It writes a `/cm <title>` header and the body through the ungated `D:Add`.
  - It reveals the console, then prints the pointer.
  - The degraded arm streams the report to chat.
- **A table serializer.** `KCM.SlashDump.Serialize` replaces `DevTools_Dump`, which prints to the chat frame. It sorts keys, indents nested tables, renders values secret-safe, and caps depth, line count and cycles.
- **Tests.** `tests/test_slash_report.lua` covers the routing rules, the reveal, the single pointer, the degraded path and the serializer.

## What the library should provide

1. **`D:Report(tag, title, fn)` on the DebugLog instance.**
   - The header takes the slash from the descriptor.
   - The pointer wording comes from the library's strings (localizable, like the diagnostics line).
   - It writes ungated, reveals the console, prints one line through the descriptor's `print`, and returns the line count.
   - The degradation stub answers with the chat fallback. Members are added to the stub, so `Kit.assertSurfaceParity` covers it.
2. **A colored view with a plain-text Copy buffer.**
   - Today `D:Add` stores one string for both the view and `D.buffer`. A colored report line (`[owned]`, `[on]`, `<-- pick`) therefore pastes out of Copy as raw `|cffxxxxxx…|r` escapes.
   - Stripping the codes in the addon would also strip the on-screen colors, and it broke ConsumableMaster's color-pinning tests. So the fix belongs in the library: keep the colored line for the view, and store the color-stripped line in the Copy buffer.
   - The diagnostics report already strips its own lines (`Out:plain`); this makes every line consistent.
3. **The serializer**, probably as a DebugLog or Core helper (`Serialize(value, opts)`), so no addon reaches for `DevTools_Dump`.

## The rollout

- Every Ka0s addon re-vendors the release, moves each report verb onto `D:Report`, and replaces every `DevTools_Dump` call.
- ConsumableMaster's local `DL.Report` becomes a one-line passthrough, and its serializer is deleted.
- A standard rule lands first, in `debug-logging` and `slash-commands`, carrying the ruling above. Then each addon's audit can check it.

## Acceptance

- `D:Report` exists, is documented in `docs/api/DebugLog/`, and has tests: ungated, reveal, one pointer, refusal writes nothing, stub fallback.
- Copy yields plain text while the view keeps its colors (test: the colored line in the view, the stripped line in `D.buffer`).
- Every roster addon routes its reports through it, and no addon calls `DevTools_Dump`.
- The standard rule is in place.
