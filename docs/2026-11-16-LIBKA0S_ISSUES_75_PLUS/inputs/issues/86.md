# #86 Standardize the header buttons on every visible window (a settings icon on all of them)

## Problem

Every visible window LibKa0s draws builds its own header controls, so the buttons in the title bar differ from window to window: which buttons appear, their order, their icons, spacing and tooltips. There is no settings button on most of them.

Each builder rolls its own today:

- `LibKa0s/DebugLogWindow.lua` — `buildTitleControls` / `buildTitleBar`
- `LibKa0s/IconBrowserWindow.lua` — `plainChrome`
- `LibKa0s/SimPanelRender.lua` — `buildChrome`
- `LibKa0s/WidgetsDragHandle.lua` — `dhBuildClose` / `dhBuildChrome` (help + close)
- `LibKa0s/PerfPanel.lua`, `LibKa0s/WidgetsCopyWindow.lua`
- `LibKa0s/OptionsSkinPicker.lua` — the only one with a settings icon (`iconButton(f, "settings", ...)`)

Consumer addons with their own windows (e.g. Drop Watcher's main window) end up making the same choice again.

## Proposal

One shared header-button strip that every visible window uses:

- A fixed, ordered set of standard buttons, right-aligned: **settings** (opens the owning addon's settings, or the window's own page), then the window's optional extras (help, lock, minimise, fullscreen…), then **close** last.
- **Settings is present on every window** by default; a window opts out only with a reason.
- One size, spacing, icon set (the LibKa0s icon set: `settings`, `help`, `close`, `minimise`, `lock`, …), hover/tooltip style and skin painting, through the existing Skin/Media paths.
- A small API, e.g. `Widgets.HeaderButtons(titleBar, { settings = fn, help = fn, close = fn, extras = {...} })`, returning the buttons so a window can add its own between the standard ones.
- Migrate the library's own windows (list above) to it; document it in `docs/api/Widgets` and `CONSUMERS.md` so addons can adopt it.

## Acceptance

- Every LibKa0s window's header shows the same buttons in the same order, with a settings button on each.
- One headless test pins the strip's order and the presence of settings and close on each library window.
- Consider whether this belongs in the Ka0s WoW Addon Standard (skinning) so addon-owned windows follow the same rule.
