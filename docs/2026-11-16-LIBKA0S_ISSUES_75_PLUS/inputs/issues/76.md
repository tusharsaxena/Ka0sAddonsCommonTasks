# #76 Move vendored Ace3 from the pinned master commit to Ace3's first tagged release with the Forever fixes

## Background

On 2026-11-07 the owner ruled that the WoW Forever port vendors Ace3 from an **untagged master commit** that contains the Forever fixes. The port does not wait for a release and does not shim. This fixes the problem once and avoids rework later, above all the AceDB profile-key change for Forever players. Context: the `docs/2026-11-07-WOW_FOREVER_PORT/` bundle in Ka0sAddonsCommonTasks.

The pinned commit brings:
- AceGUI CheckBox **v27**, which calls `check:SetDesaturated`. Retail 12.1.0 and Forever 1.60.1 both removed the global `SetDesaturation`; `/dump SetDesaturation` returns nil on Retail.
- ColorPicker **v29**, which stops inverting alpha on Forever.
- AceDB **MINOR 36+**, which builds Forever profile keys from the ruleset and surname, not the realm.

These fixes are on master at ac3d1225 or later, and no tagged release contains them yet.

## To do when Ace3 tags a release that includes the pinned commit

1. Re-vendor Ace3 from that tag into every roster addon, and record the tag instead of the commit in each addon's provenance.
2. Diff the tag against the pinned commit. Nothing Ka0s relies on should change, and AceDB's MINOR must not change the profile-key scheme.
3. Run each addon's green gate, then an owner smoke on both clients.

Related: #44 (WoW:F client support).
