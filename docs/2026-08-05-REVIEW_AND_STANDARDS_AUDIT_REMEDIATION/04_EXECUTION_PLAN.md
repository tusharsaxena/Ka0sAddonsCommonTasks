## Standing verification, every item

Unless an item says otherwise, "verified" means all of the following in the repo touched:

```
luacheck .                                              # 0 warnings / 0 errors
lua5.1 tests/run.lua                                    # 0 failed
lizard -l lua -x "./libs/*" -x "./tests/_kit/*" .       # Warning cnt 0
git status --porcelain                                  # only the intended paths
```

Where a case count is expected to move, the item says the expected delta. Where `docs/test-cases.md` is
regenerated, `lua5.1 tests/run.lua --list > /tmp/list && diff <(tr -d '\r' < /tmp/list) <(tr -d '\r' < docs/test-cases.md)`
must be empty — **CR-normalize both sides**; the runner's own output is CRLF in several repos.

Today's baselines, for comparison: AbsorbTracker 470, BankLedger 726, ConsumableMaster 656, KickCD 737,
LootHistory 579, PanelMaster 706, prettychat 255, WhatGroup 422, LibKa0s 480.

**Every "Verified by" command must be shown failing before it is accepted.** Plant a deliberate violation,
run the command, see it red, revert, see it green. A verification that cannot go red is the same defect
cluster C16 exists to fix, and two shapes of it were found in this document during review:

- **`grep -cE '…' settings/` with no `-r`** reports `grep: settings/: Is a directory` and exits non-zero,
  which reads as "no matches" to anyone scanning output. Fixed in `M4-27`.
- **Alternation pipes copied out of a table cell.** In these tables `\|` is **GFM escaping** and renders as
  a literal `|`, so the *rendered* `grep -rniE "colour\|grey"` is a correct ERE. Copy it from the **raw
  markdown** instead and you get a pattern where `\|` matches a literal pipe character — the single string
  `colour|grey`, which appears nowhere and can never fire (verified: against a file containing both words,
  the backslash form exits 1 with no output; the plain ERE matches both). Strip the backslashes when you
  copy from source.
