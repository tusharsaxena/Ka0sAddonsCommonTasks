# 05 — Traceability

**Every one of the 207 surviving findings mapped to a cluster, a milestone and a work item — and the
seven that are not.**

> **Nothing in this bundle has been executed.** No repository outside this directory has been read for
> anything but evidence. Every work item named below is unstarted; every disposition is a proposal.
> See `00_OVERVIEW.md`.

This document is the plan's own audit. Its job is to fail loudly where `04_EXECUTION_PLAN.md` does not
cover something `01_CONSOLIDATED_FINDINGS.md` found, and it did: **seven findings had no work item**,
four of them specified in `03_SPEC.md` and scheduled nowhere, three in neither. They are named in Part 3
with the item each needs. An eighth, `KICKCD-R-02`, was in that list until it was measured against the
release gate it blocks, and it is now `M4-25`; the change is recorded rather than quietly applied,
because a coverage number that only ever falls is a number nobody is checking. A traceability document
that reports 207/207 is a document that has stopped looking.

---

## The rule

Every finding gets exactly one row and exactly one work item. A finding with no work item still gets a
row, marked **UNMAPPED**, and its absence is stated as a defect in the plan rather than dressed as a
deferral. Silence is not allowed in either direction: Part 5 gives every work item that closes no
finding a reason to exist.

Where a finding is filed against an addon but fixed upstream, the **Work item** column names the item
whose completion closes it *in the repository the finding is filed against* — `ABSORBTRACKER-R-08` is
`M3-03`, not `M1-LK-02`, because AbsorbTracker's vendored copy is still broken until the re-vendor lands
and its private workaround comes out. The upstream prerequisite is in the plan's own **Depends on**
column and in Part 6's reverse index.

**Disposition** says what closing the item actually does, because "mapped" and "remediated" are not the
same claim:

| Disposition | What closing the item does | N |
|---|---|---|
| `fix` | Code, config or documentation changes. | **156** |
| `record-regen` | The automated-test record is regenerated by the runner. Nothing is hand-written and no source moves. | **14** |
| `fix-forward` | The frozen artifact is **deliberately left alone**; the next run writes what is missing and the gap is noted once. The cited bundle stays as it is, permanently. | **9** |
| `register-row` | A ratified deviation is recorded in `docs/ARCHITECTURE.md`. The cited code is untouched. | **9** |
| `rule-change` | The standard changes; the cited code becomes compliant by definition. | **8** |
| `deferred` | Partially closed at best, with a written reason and a named later tag. All four are `C12`. | **4** |
| **UNMAPPED** | **No work item exists. A defect in the plan — see Part 3.** | **7** |

`156 + 14 + 9 + 9 + 8 + 4 + 7 = 207` ✓

**Forty of the 207 close without the cited code changing** — the `record-regen`, `fix-forward`,
`register-row` and `rule-change` rows. That is disclosed here rather than left to be inferred from a
"207 mapped" headline.
