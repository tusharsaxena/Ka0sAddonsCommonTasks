## AceDB 33 to 40: what changed

1. **Character key.** 33 built `UnitName("player") .. " - " .. GetRealmName()`. 40 builds
   `UnitNameUnmodified("player") .. " - " .. GetRealmName()` on the non-Forever path. `UnitNameUnmodified` differs from
   `UnitName` only where the client rewrites a unit's displayed name (name modifiers such as Mercenary or
   disguise-style effects, and the Forever regional-unique-names scheme). For the player on a normal Retail login the two
   return the same string, so the key is the same.
2. **Forever branch.** The new realm/char keys (`PvE`, `PvP`, `RP`, `RP-PvP`, `Hardcore`; `name surname`) sit entirely
   behind `if RegionalUniqueNamesEnabled and RegionalUniqueNamesEnabled() then` (AceDB-3.0.lua:263). That global is
   absent on Retail, so Retail always takes the `else` branch. Class, race, faction, region keys are computed as before
   (region now treats an empty `GetCurrentRegionName()` as nil, which cannot affect a live region).
3. **Profile-name validation (new).** At `AceDB:New`, an existing `profileKeys[charKey]` that is not a string, or has
   length 0, length over 50 (UTF-8) or is all spaces, is reset to `defaultProfile or charKey`. `SetProfile(name)` and a
   string `defaultProfile` raise on those same names.
4. **Ka0s exposure to (3).** Grep of every roster addon (outside libs/, tests/, docs/): every `AceDB:New` call passes
   `true` (never a string) or no default profile, so the `defaultProfile` check never fires. No addon defaults or
   migration writes a profile name; the only `SetProfile` callers are the `/at` and `/pfe` profile slash verbs, which
   pass a user-typed name. Realistic profile names ("Default", character keys such as `Thrall - Area 52`, user names
   under 50 chars) are untouched. Residual: a user whose saved profile name is empty, spaces-only or over 50 chars (only
   reachable by hand-editing SavedVariables, since 33 had no limit but AceDBOptions offered no such name in practice)
   would be reset to the character key, and typing a name over 50 chars into `/at profile set` or `/pfe` now raises an
   error where 33 accepted it. AceDBOptions 17 validates the same limit in the UI.

## test_acedb_retail_key_stable (headless, real AceDB files)

Loads the real vendored MINOR 33 and the real `ac3d1225` MINOR 40 `AceDB-3.0.lua` with LibStub and CallbackHandler,
stubs the Retail globals (`RegionalUniqueNamesEnabled` nil, `UnitNameUnmodified == UnitName`), opens an SV holding
`profileKeys` for the player and another character, and prints every key and the resolved profile.

```lua
-- usage: lua acedb_key.lua <Ace3 root with LibStub, CallbackHandler-1.0, AceDB-3.0> <label>
local root, label = arg[1], arg[2]
strlenutf8 = function(s) return #s end  -- ASCII fixtures only
function UnitName() return "Thrall", nil end
UnitNameUnmodified = UnitName            -- Retail: same for the player (no modifier active)
function GetRealmName() return "Area 52" end
function UnitClass() return "Shaman","SHAMAN" end
function UnitRace() return "Orc","Orc" end
function UnitFactionGroup() return "Horde" end
function GetCurrentRegion() return 1 end
function GetCurrentRegionName() return "US" end
function GetLocale() return "enUS" end
function IsLoggedIn() return true end
function CreateFrame() return {SetScript=function() end, RegisterEvent=function() end} end
local function load(p) local f=assert(loadfile(root.."/"..p)); return f("x", {}) end
load("LibStub/LibStub.lua"); load("CallbackHandler-1.0/CallbackHandler-1.0.lua"); load("AceDB-3.0/AceDB-3.0.lua")
local AceDB = LibStub("AceDB-3.0")
-- existing SV: key "Thrall - Area 52" -> "Default"; plus a non-pathological string-named profile
local sv = { profileKeys = { ["Thrall - Area 52"] = "Default", ["Old - Area 52"] = "My Profile" },
             profiles = { Default = {}, ["My Profile"] = {} } }
local db = AceDB:New(sv, {profile={x=1}}, true)
print(label, "minor", select(2, LibStub("AceDB-3.0", true)),
      "keys:", db.keys.char, "|", db.keys.realm, "|", db.keys.factionrealm, "|", db.keys.factionrealmregion,
      "| profile:", db:GetCurrentProfile(), "| Old kept:", sv.profileKeys["Old - Area 52"])
```

Run as `lua acedb_key.lua <dir-with-LibStub-CallbackHandler-AceDB 33> v33` and again against the `ac3d1225` clone:

```
v33	minor	33	keys:	Thrall - Area 52	|	Area 52	|	Horde - Area 52	|	Horde - Area 52 - US	| profile:	Default	| Old kept:	My Profile
v40	minor	40	keys:	Thrall - Area 52	|	Area 52	|	Horde - Area 52	|	Horde - Area 52 - US	| profile:	Default	| Old kept:	My Profile
```

Identical in every field.
