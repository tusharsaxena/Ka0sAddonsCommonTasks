Ka0s skins: header and icon border sign-off

Smoke round 4, item R4-MOCK (bundle docs/2026-11-03-SMOKE_ROUND4, owner feedback items 4 and 6). Every value on this page is a token read from LibKa0s/LibKa0s/SkinDefs.lua (DEFS_MINOR 26) and SkinDefsOthers.lua (minor 8) on branch feat/2026-11-01-full-skinning: both files were loaded under a stub LibStub in lua5.1 and each skin resolved as Skin:ResolveSkin does (Ka0s Default's tokens with the skin's own over them, false dropped). Nothing is guessed; the only stand-ins are client art CSS cannot draw, and each is captioned.

  • Registered skins, in registration order: Ka0s Default, Obsidian, Azeroth, Glass, High Contrast, Ember, WoW Default, WoW Midnight, WoW Forever. No other skin is registered. The EllesmereUI source (eui) is a source, not a registered skin, and is not shown.
  • Alphas composite over a dark game-world backdrop, #1a1c2a, so translucent skins (Glass, Ka0s Default) look as they do in game. The contrast figures below were measured over black, as LibKa0s' tests measure them.
  • The header band is painted once, at title.height 30 px, as windows that pass noTopBar paint it and as the Showroom will once R4-ST4 fixes its double paint. Today's Showroom stacks title.bg twice, so Glass's 0.10 white band and Ka0s Default's 0.90 black band read denser in /skintester than here.
  • Fonts are the system UI face here. The in-game face and sizes are under each card (sizes on this page are 1.1x the token size, for legibility). Window text is outlined in game (font.outline OUTLINE); a faint outline stands in for it here.

1. Every skin, header and main elements

Each card: the window edge (win.border, win.borderSize, win.inner 1 px inside it), a 30 px header band (title.bg, or the title.bgTop to title.bgBottom gradient; title.text; title.align; close glyph in close.rest), then body and dim text, a button and a primary button, a dropdown and its arrow (icon.arrow), a tab strip (selected first), a table header with a plain, a striped and a selected row, a checkbox, a statusbar (bar.bg, bar.fill, bar.border when bar.borderStyle is not None) and an icon with its 1 px icon.border.

What else the header choice moves

  • MultiMeters' meter header strip follows title.bg (Window_Header.lua, flat SetColorTexture while header.bgColorFromSkin is on), so the in-combat meter header turns olive (A, B, E) or grey (C, D) under Ka0s Default. It ignores the gradient pair, so under E it draws the flat blend #2C2408. MultiMeters' NS.SKIN_FALLBACK copy of title.bg (core/SkinSetup.lua) moves in the same sweep, or its test goes red after the re-vendor.
  • Every window that paints S.Shell or S.TitleBar: every addon's SkinSetup, BankLedger, LootHistory, DropWatcher, MultiMeters, PGFE, QuickComms modal and WhatGroup's FrameSkin windows, and the Showroom. The settings panel's page header uses title.text and title.rule, not title.bg, so it does not change.
  • QuickComms' pad header band (qc.bandBg) follows title.bg but defaults to clear under Ka0s Default, so it does not change.
  • D also moves divider, which must move Core.SKIN.divider with it: every Core.ApplySkin divider and the Widgets menu rule brighten to #55555F.
  • B equals Ka0s Default's primary button fill, so a primary button in a title bar would sit on its own colour, separated only by its gold edge.
  • Optional: the Ka0s Default picker swatch (second of four, #000000) can become the new header colour.

What else the icon border choice moves

  • Option 1, one token (icon.border). The same token is the HUD icon edge in every host that follows the skin: AuraMaster (Style_Border), KickCD (IconGrid_Render, Castbar_Skin), DropWatcher (IconStyle), QuickComms (IconStyle), DpsRace (Results_Gear), and ConsumableMaster's button border (cm.buttonBorder). Under Ka0s Default those edges go from black to #4D4D57; in Glass, Ember, Forever and Midnight they lighten as shown. DpsRace's and QuickComms' library-absent fallback copies of {0,0,0,1} move to the new grey too. Consistent with Obsidian, whose HUD edges are already grey.
  • Option 2, a separate icon.outline token. S.IconBorder reads icon.outline first, falling back to icon.border; the HUD hosts keep today's edges (black under Ka0s Default, which reads well over the game world). Caveat: S.SquareIcon draws its own 1 px edge straight from icon.border, so it would need the same fallback or keep the faint edge underneath.
  • The EllesmereUI source derives icon.border from ElvUI's panel colour, so neither option changes its outlines.

4. How to reply

  1. Header: A, B, C, D, E, or Now (keep). Add "flat" or "gradient" if you want E's shape in another colour. Example: "Header: A".
  2. Picker swatch: "Swatch: header" (second swatch becomes the new header colour) or "Swatch: keep".
  3. Icon borders, which skins: "Icon borders: proposed, all skins" (Ka0s Default, Glass, Forever, Ember, Midnight), or name them, e.g. "Icon borders: proposed, Ka0s Default + Glass".
  4. Icon borders, scope: "one token" (option 1) (HUD edges change too) or "icon.outline" (option 2: window outlines only, HUD stays).
  5. Full example: "Header: A; Swatch: header; Icon borders: proposed, all skins, one token".
